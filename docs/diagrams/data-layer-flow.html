How Java code becomes a row in Postgres

Two companion pictures to Fig. 1/2 of the Runtime Flow diagram: the layers between your @Entity class and real SQL, and what actually happens to those layers the moment the backend starts up.

1. The layers between your code and SQL

Four names that get blurred into one: JPA is a contract, Hibernate fulfills it, Spring Data JPA makes it convenient to call, and Spring Boot wires all three together automatically.

2. What happens at backend startup

One physical connection path (host process → JDBC → Docker's port mapping → the Postgres process inside the container), used for three different jobs, in a fixed order, every time the app starts.

3. Why Flyway is guaranteed to run before Hibernate checks anything

Not a timing coincidence — an enforced dependency between two Spring "beans." Traced against the real failure hit while building this project.
